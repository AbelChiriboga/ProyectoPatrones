# Política de trabajo

- Priorizar PDFs académicos de `../docs`, código de origin/main y evidencias verificables.
- Trabajar en rama local semana3-ventas; conservar main y cambios ajenos. No reset, stash, commit, push ni PR.
- SDD-03.1 autoriza implementar semana 3 y una prueba P09 trazable en la instancia aislada del proyecto. Seguir docs/sdd/semana3/especificacion.md; actualizar PROGRESS.md (máximo 35 líneas).
- Conservar contratos y código validado; separar Domain, Application, Infrastructure y UI en ambas aplicaciones.
- Ejecutar build y pruebas pertinentes; distinguir integración real, omisiones y evidencia histórica.
- Flujo React → .NET → Odoo; sin acceso directo a PostgreSQL ni claves en navegador/Git/logs.
- No instalar software global, borrar volúmenes, alterar seguridad existente ni registrar ventas sin autorización explícita.
- No reintentar escrituras inciertas a ciegas. Reportar estado real, archivos, pruebas y próximo bloque brevemente.

- Codex inspecciona y modifica mediante terminal; verifica con pruebas automatizadas, compilaciones, HTTP y comandos de procesos/puertos/servicios.

- Antes de iniciar servicios, comprobar la ruta del proceso: este repo está en patrones-software-semana3/ProyectoPatrones. Detener solo el proceso incorrecto identificado, sin afectar otros servicios.
- No cambiar secretos/credenciales ni registrar nuevas ventas reales sin autorización. Sin commits, push ni merges.
- Ejecutar intervenciones completas y autónomas, con resultados breves, comprobables y sin confirmaciones innecesarias.
